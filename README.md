# 协同进化（Coevolution）· 1v1 单挑

以代号为单位的 1v1 卡牌对战：每个代号拥有自己的 12 张私有牌组，用三张基础牌（打击 / 防御 / 风暴）起手，并在对局中通过**奖励三选一**获得十张新卡、升级初始牌、移除低质量牌或回复体力，直到一方阵亡。
纯前端单机，玩家操作一方，另一方由规则式 AI 驱动。

- 技术栈：Vue 3 + TypeScript + Vite 8 + Tailwind CSS v4
- 规则引擎：纯 TypeScript、零 Vue 依赖、状态可序列化、随机确定性
- 测试：vitest 单元测试（含 200 局 AI 自对局不变式校验，用例数见 `npm test` 输出）

```bash
npm install
npm run dev            # 开发服务器
npm test               # 运行全部测试
npm run lint           # ESLint 静态检查
npm run format:check   # Prettier 风格检查
npm run typecheck      # vue-tsc 类型检查
npm run build          # 类型检查 + 生产构建
```

## 卡牌

卡牌只有**卡面效果**与**费用**：没有花色，也没有点数——`types.ts` 的 `Card` 只有 `uid` 与 `kind`，
效果与费用写在 `data/cardDefs.ts`，同名卡牌之间完全等价。

### 威胁：本作唯一的基础伤害机制

攻击**不直接扣血**，而是给目标叠加**威胁**：

1. A 的回合，A 攻击 B → **B 获得威胁**（体力不变）。
2. B 的回合，B 可以打出【防御】抵消自己的威胁（1 张抵消 1 点）。
3. **B 的回合结束时**，B 剩余的威胁结算为等量伤害（走伤害帧：「受到伤害后」技能 → 濒死检查），随后归零。

威胁**不跨回合累积**：它只在「施加者的回合」与「承受者回合结束」之间存活一轮，因此每个威胁都恰好给承受者一次应对机会。
所有攻击类内容（【打击】/【风暴】/【强袭】）都只经由 `threat` 指令走这一条路径；
唯一的例外是「失去体力」（`lose-hp`：技能的自伤与【消耗战】的流失），它不是伤害，直接扣血、不触发「受到伤害后」技能。

### 三张基础牌

| 牌 | 能量 | 卡面效果 |
|---|---|---|
| **打击** | 1 | 令对方获得 1 点威胁（数值走 `threat-per-attack` 通道，可由技能修正）。**没有次数限制**，有多少能量就能打几张。 |
| **防御** | 1 | **在自己的出牌阶段**抵消自己 1 点威胁（自己至少有 1 点威胁时才能使用）。 |
| **风暴** | 2 | **多目标**：令每名角色（包括你自己）获得 2 点威胁。 |

费用是**按牌种的固定值**（`data/cardDefs.ts` 的 `cost`）：打击 1 / 防御 1 / 风暴 2。

> **回血牌已整体删除**：旧的【回复】【回复+】【急救】【急救+】连同其卡牌文档一起移除，牌组里不再有任何回血牌；
> 唯一的回血来源是奖励三选一里的「回复 1 点体力」。**没有任何牌声明 `dying` 语境，因此濒死即阵亡**。
> 引擎与 DSL 仍保留 `dying` 语境与 `resolve-dying` 指令（测试用合成牌 `test-mend` 覆盖这条链路，见 `fixtures.ts`）。

【打击】与【防御】是同一套威胁机制的两端；【风暴】验收了**多目标**（`TargetSpec.count` + `for-each-target`）；
「使用时选目标」（`UseVariant.target` + `cardTargetChoice`）这条机制改由测试注入的合成牌验证。
这些牌都只是 JSON，引擎、legality、AI 与界面里没有任何牌种分支。

### 奖励池：十张新卡与三张升级版

奖励池由 **`rarity` 字段**结构性定义（`rules/reward.ts` 的 `rewardPool()`）：只有声明了稀有度的牌种才可能被抽到；
基础牌与升级版都不声明 `rarity`，因此不会出现在奖励候选里（也没有任何牌种 id 写死在代码里）。

| 新牌 | 能量 | 稀有度 | 效果 |
|---|---|---|---|
| 连击 | 1 | 普通 | 令对方获得 2 点威胁 |
| 铁斩波 | 1 | 普通 | 令对方获得 1 点威胁，并抵消自己 1 点威胁 |
| 后空翻 | 1 | 普通 | 抵消自己 2 点威胁并摸 1 张牌（需自己有威胁） |
| 战术演习 | 1 | 普通 | 摸 2 张牌 |
| 痛击 | 2 | 稀有 | 令对方获得 3 点威胁 |
| 血怒 | 1 | 稀有 | 自己失去 1 点体力，令对方获得 3 点威胁（失去体力不触发【反击】） |
| 重压 | 2 | 稀有 | 令对方获得 `min(⌊手牌数 / 2⌋, 1..4)` 点威胁 |
| 掠夺 | 1 | 稀有 | 随机弃置对手 1 张手牌（对手需有手牌） |
| 疾跑 | 1 | 稀有 | 本回合额外进行一次摸牌阶段 |
| 重锤 | 3 | 史诗 | 令对方获得 5 点威胁 |

三张基础牌各有一张**独立牌种**的升级版（`id` 用 `-plus`、`name` 用 `+`），通过卡牌文档的 `upgradeTo` 指向：

| 升级版 | 变化 |
|---|---|
| 打击+ | 威胁 = `threat-per-attack` 通道 + 1（保留通道语义，不是写死 2） |
| 防御+ | 抵消自己 2 点威胁 |
| 风暴+ | 令每名角色获得 3 点威胁 |

升级是**就地改 `kind`**（`uid` 不变），因此升级不改变牌数守恒，也不影响摸牌与洗回；升级版本身**不得再声明 `upgradeTo`**（禁链式升级，加载期校验）。


### 私有牌组（每代号 12 张，三套）

| 牌组 | 构成 | 代号 |
|---|---|---|
| `basic` | 打击 8 / 防御 4 | 反击型 |
| `aggressive` | 打击 8 / 防御 3 / 风暴 1 | 进攻型、转化型 |
| `guarded` | 打击 7 / 防御 5 | 防御型 |

牌组是**私有**的：每个代号（即每位玩家）拥有自己的 12 张牌组与自己的弃牌堆，摸牌只从自己的牌组摸，
自己的牌组耗尽时也只把**自己的**弃牌堆洗回自己的牌组，双方互不干扰。

按代号分化牌组只需新增/替换一份牌组 JSON 并改代号文档的 `deck` 字段：uid 分配（玩家 0 从 0 起、玩家 1 接续）与守恒校验都由牌组文档推导，不需要改代码。
三套牌组是平衡旋钮（见文末「平衡观察」）：防守牌组给防御型更多【防御】，攻击牌组给进攻型、转化型【风暴】但少一张【防御】。

### 基础规则术语

| 术语 | 含义 |
|---|---|
| 阶段 | 回合被划分成的固定步骤，顺序为准备 → 判定 → 摸牌 → 出牌 → 弃牌 → 结束 |
| 时机 | 引擎在固定时点执行规则效果的位置，如「回合开始时」「阶段开始时」「阶段结束时」 |
| 威胁 | 攻击造成的结果，记在**承受者**身上；承受者在自己的出牌阶段用【防御】抵消，回合结束时剩余多少威胁就受到多少伤害 |
| 伤害 | 只在回合结束时由威胁结算产生（另有技能自伤／【消耗战】的「失去体力」直接扣血，不算伤害） |
| 摸牌数 | 摸牌阶段摸几张牌，默认 5 张（`draw-count` 通道基准）；先手角色的第一回合 4 张；技能可按通道修正 |
| 手牌上限 | 弃牌阶段结束时允许保留的手牌数，默认 `min(当前体力, 6)`（`hand-limit` 通道是额外偏移，基准 0；封顶值 `HAND_LIMIT_MAX = 6`）。体力上限提到 10 之后若不上限，手牌会随体力膨胀到 10 张而出牌能量远付不起，因此封顶 6。结算顺序是「弃牌 → 回合结束时威胁结算」，所以上限按**结算前**的体力算 |
| 奖励 | 「回合开始时」触发的三选一：第 3 的倍数回合是**卡牌三选一**（可跳过，选中的牌直接进手牌），第 4 的倍数回合是**服务三选一**（升级 / 移除 / 回复 1 点体力）；两者都命中时卡牌先弹、服务后弹，双方各选一次 |
| 能量 | 使用／打出卡牌要支付的资源，按牌种费用加 `card-cost` 通道修正计（**下限恒为 1**）；**回合开始时回复至上限**（默认 3 点） |
| 上限 | 能量的最大值，由基础值加技能修正得来（【蓄能】+2） |
| 跳过阶段 / 额外的阶段 | 本回合计划中删去某个阶段，或额外插入一个阶段 |

## 对局流程

1. 开局从 4 个代号中随机抽 3 个，玩家选 1 个；AI 从「除玩家所选之外」的代号中随机选 1 个。
2. 双方各自洗一副 12 张的私有牌组，各摸 4 张起手牌；玩家先手，**先手第一回合少摸 1 张**，此后每回合摸 5 张。
3. 回合流程（六阶段）：
   **回合开始时 → 准备阶段 → 判定阶段 → 摸牌阶段 → 出牌阶段 → 弃牌阶段 → 结束阶段 → 回合结束时**。
   - 每个阶段再分为「阶段开始时 → 阶段进行 → 阶段结束时」，规则效果注册在时机上（`rules/phase.ts`）；引擎**先把游标移到下一个子步骤再产生效果**，所以濒死等结算打断流程后不会重复执行同一个子步骤。
   - 摸牌阶段：默认摸 5 张（先手第一回合 4 张）。
   - 出牌阶段：能量在回合开始时已回满，能付几张【打击】就打几张（没有次数限制），每张给对手叠威胁；也可以打出【防御】抵消自己身上的威胁；可发动主动技。
   - 弃牌阶段：手牌上限 = `min(当前体力, 6)`，超出部分须弃置（摸 5 张后经常需要弃牌）。
   - 回合结束时：先执行时机效果，然后**结算自己的剩余威胁**（等量伤害），再切换回合。这是威胁唯一的兑现点。
   - 准备 / 判定 / 结束阶段本作没有可结算的内容，保留为空阶段与时机扩展点。
   - 阶段可被**跳过**（`skipPhase`）或插入**额外的阶段**（`addExtraPhase`），作用于本回合剩余的阶段计划 `state.phaseQueue`。
4. **回合开始时的奖励三选一**（`refillEnergy` 之后、摸牌阶段之前）：
   - **卡牌三选一**（`turn % 3 === 0`）：按稀有度权重 `common/uncommon/rare = 60/30/10` 抽 3 张不重复的牌，可以跳过；选中的牌**直接进手牌**（`cardTotal += 1`，uid 由 `state.nextUid` 分配）。
   - **服务三选一**（`turn % 4 === 0`）：升级一张自己的牌 / 移除一张自己的牌 / 回复 1 点体力（满血禁用）；移除后「牌组 + 手牌 + 弃牌堆」不得少于 5 张。
   - 两份规则文档挂在同一时机上（`rules/reward-card.json` priority 30、`rules/reward-service.json` priority 20），`offer-reward` 只**压帧**不立即询问，因此规则先执行的服务反而后弹；两者都排在消耗战（priority 10）之后，**先扣血、扣死了就不再发奖励**。
   - 询问顺序从回合角色起按座次，**双方各选一次**；升级 / 移除的候选是本人的「牌组 + 手牌 + 弃牌堆」（按 uid 升序，不含移除区），因此非回合角色也会被询问。
5. **单将决胜**：任意一方体力归零即败；**濒死时没有任何牌可以自救**（内容层没有 `dying` 语境的牌），因此进入濒死基本等于阵亡。

### 结算链（完备性说明）

- **使用【打击】**：合法性校验（牌面选项 + **能量是否够付** + **目标是否合法**）→ 支付能量 → 指定目标 → 按 `threat-per-attack` 通道给目标叠威胁（基础 1，可由技能修正）。
  期间**没有响应窗口**：对手只能在**自己的回合**用【防御】抵消。
- **打出【防御】**：在自己出牌阶段的合法动作，文档 `requires` 要求自己至少有 1 点威胁；支付 1 点能量 → 自己的威胁 −1。
- **威胁结算**：承受者的「回合结束时」把剩余威胁一次性转成伤害（`resolveThreatAtTurnEnd`），先归零再走伤害帧——「受到伤害后」技能（【反击】，人类玩家可选发动）→ 濒死检查。
- **「失去体力」≠「受到伤害」**：技能自伤与【消耗战】直接扣体力，不触发「受到伤害后」技能，但同样会进入濒死；它们也不经过威胁。
- **使用卡牌时的目标选择**：【打击】（唯一候选对手）、【防御】（自己）沿用文档缺省目标；
  声明了 `target`（如 `scope: any` + 已受伤条件）且候选不唯一时必须由玩家选定，
  界面进入目标选择态后再提交（`Action.use-card.targets`）。可用性与提交共用 `cardTargetChoice`，**按得到就必然提交得成**。
  内置内容已无这类牌，机制由测试注入的合成牌（`fixtures.ts` 的 `test-aid` / `test-mend`）验证。
- **多目标**：`TargetSpec.count` 支持 `all`（作用于全部合法候选，如【风暴】同时给双方叠威胁）与 `exactly`（必须选够 N 个）。
  多目标变体的效果写在 `for-each-target` 指令里，逐个把 `target` 绑定为当前目标执行；
  多目标下**不绑定** `target`，直接引用会在加载期被校验器拒绝，避免"以为打了全体却只打了一个"。
- **濒死**：从濒死者开始按座次询问所有存活角色是否使用「`dying` 语境」的牌；可连续使用直到体力回到 1 以上；队列耗尽则死亡。
  **当前内容没有任何 `dying` 语境的牌，因此双方都只能放弃、濒死即阵亡**；引擎的救援链路仍由合成牌 `test-mend` 的测试守护。
- **死亡**：标记阵亡 → 弃置全部手牌（进自己的弃牌堆）→ 清空未结算的威胁 → 清空结算栈与处理区（按条目归属分流）→ 判定胜负。
- **牌数守恒**：任意结算步之后，全部牌恰好属于「自己的牌组／手牌／自己的弃牌堆／自己的移除区／处理区」之一，且 uid 全局唯一，引擎在每次 `submit` 后自动校验。
  基准是 `state.cardTotal`（初始 = 双方牌组张数之和 24）；奖励三选一会**加牌**（同步 +1），移除只是把牌挪进移除区（总数不变），因此守恒断言不需要放宽。
- **奖励结算**：`offer-reward` 在「回合开始时」压入奖励帧；`stepFrame` 先按 `ask` 队列逐个询问（卡牌候选在压帧时一次抽好，服务可用性当场现算），选定「升级 / 移除」后再出 `pick-card` 选牌。升级就地改 `kind`、保留 `uid`；移除把牌 push 进 `players[p].removed`；每个动作都会写一行战报，玩家能看到对手的奖励结果。
- **牌组耗尽**：某方把自己的弃牌堆洗回自己的牌组；两者同时为空则跳过摸牌并记录日志。

结算顺序由显式的**结算帧栈**驱动（`threat → damage → dying → flush`），而不是散落的回调，因此顺序可测、可读、可扩展。

### 对抗机制（占位）

历史上【打击】会开启响应窗口、由目标打出【防御】抵消，这套机制（`contest` / `contest-contribute` 指令、
`respond` 询问、`play-card` 动作、卡牌 `play` 变体、`defend-need-against` 通道）在本作改为威胁机制后**没有任何内容使用**。
它被**刻意保留**为后续反制机制的占位：DSL 词表、引擎结算帧、legality、AI 与界面的响应分支都还在，
`dsl/effect.test.ts` 与 `dsl/channels.test.ts` 用合成内容继续守护它，但内置卡牌一张都不再声明 `play` 变体。
新增反制内容前请先想清楚它与威胁机制的关系，不要照抄旧例。

### 能量系统

| 规则 | 内容 |
|---|---|
| 上限 | 每人 3 点；【蓄能】与【转换】各 +2（防御型、转化型 5 点） |
| 回复 | **回合开始时回复至上限**，只回复回合角色的能量；没花完的余额留在池中（不超过上限） |
| 付费范围 | **所有使用与打出**：出牌阶段使用任意牌（含奖励新卡与升级版）、濒死使用 `dying` 语境的牌（当前内容没有，救援者付自己的能量） |
| 费用 | 按「**当作的牌面**」计：打击 1 / 防御 1 / 风暴 2 |
| 不付费 | 主动技（如【强袭】）、弃牌阶段的弃置、技能的费用弃牌 |

三个直接推论：

1. **防御与进攻争同一份能量**。能量只在自己回合开始时回满，所以「这回合多打两张【打击】」与「先把身上的威胁抵消掉」是一对取舍；留到下回合的能量不会累积，先花掉反而更划算。AI 也按这条行事（先清威胁，再花剩下的能量进攻）。
2. **威胁拖到下回合才兑现，但不会消失**。对手的攻击在你**下个回合结束时**才变成伤害，你有一整个回合决定用多少能量、多少张【防御】去抵消它；扛下伤害则意味着你能把能量全用来进攻。
3. **濒死没有自救牌**。内容层已删除全部回血牌，被打进濒死就只能阵亡；保住体力只能靠奖励里的「回复 1 点」。**任何牌面的费用都不允许为 0**（0 费 + 无次数限制 = 无限连击，`energy.test.ts` 对此有断言）。

能量与「牌数守恒」「威胁非负」一样是硬不变式：任意结算步之后必须落在 `0..上限` 之内，引擎在每次 `submit` 后自动校验（`assertEnergyBounds` / `assertThreatBounds`）。

参数在 `src/game/rules/energy.ts`（`BASE_ENERGY_MAX`）与 `src/game/data/dsl/cards/*.json`（每张牌的 `cost`）。

### 消耗战（终止规则，重要）

牌组会无限洗回，【转换】又可以把每张【打击】都当【防御】抵消掉威胁，因此对局存在天然的僵持：双方只要都愿意把能量花在抵消上，就能一直不受伤（回血牌删除后僵持更少见，但抵消循环仍在）。

因此从**第 21 回合**起进入消耗战：每个回合的「回合开始时」时机，回合角色**直接失去体力**（`lose-hp`，不经过威胁、不可被【防御】抵消），每 5 回合递增 1 点（`1 + ⌊(回合 − 21) / 5⌋`）。流失量无上限增长，最终必定超过任何回复能力，保证对局必然结束。能量的回满发生在这条效果之前，所以因消耗战进入濒死的角色是带着满能量被询问的。

消耗战不是写在流程里的特例，而是**一条 DSL 规则文档**：`src/game/data/dsl/rules/attrition.json`
挂在「回合开始时」时机上，与技能触发走同一条通路（`dsl/event.ts` 的时机派发）。
回合数、递增步长、流失量表达式都在文档里；`rules/turn.ts` 只保留 `ATTRITION_TURN` /
`ATTRITION_STEP` / `attritionLoss()` 供界面提示与测试断言，并由 `turn.test.ts` 断言两者一致。

## 代号与技能

四个代号一律以「型」结尾，`name` 直接描述玩法；代号文档不再有 `emoji` 字段，界面与战报只显示代号文本。

| 代号 | 体力 | 技能 | 类型 | 效果 |
|---|---|---|---|---|
| 进攻型 | 10 | **强袭** | 主动 | 出牌阶段限一次：弃置一张手牌，令对方获得 2 点威胁 |
| 反击型 | 10 | **反击** | 触发 | 当你受到伤害后，你可以令伤害来源获得 1 点威胁 |
| 防御型 | 10 | **蓄能** | 常驻 | 你每回合的能量上限 +2（3 → 5） |
| 转化型 | 10 | **转换** | 转化 + 常驻 | 你可以将【打击】当【防御】、【防御】当【打击】使用；能量上限 +2（3 → 5） |

> 代号 id 分别是 `offensive` / `counter` / `defensive` / `morph`（`transform` 会与 DSL 的转化词表冲突，故用 `morph`）；
> 技能 id 是 `assault` / `riposte` / `charge` / `convert`。

本轮把原本 8 个动物物种精简为 4 个功能代号：代号名与技能名都改成中性的功能词（强袭 / 反击 / 蓄能 / 转换），并去掉形象图标。
被删去的 4 个技能（【疗愈】【威压】【狡黠】【透支】）连同其代号一并退役；
需要「选目标 / 多候选 / 缺省不合格」这类通用机制的测试改用合成内容（见 `skills/active.test.ts`、`stores/game.test.ts`）。

上表的每个技能都是**一份 JSON 文档**（`src/game/data/dsl/skills/*.json`），行为由 DSL 解释器执行；
引擎、合法性判定、AI、界面里**不存在任何技能 id 分支**（由 `dsl/guards.test.ts` 机械守卫）。

转化类技能产生的牌统一用 `VirtualCard` 表示（`as` = 当作什么牌，`source` = 实际消耗的牌，`via` = 技能），威胁、日志、弃牌全部只认它，避免结算与展示分叉。

## 内容 DSL（技能 / 卡牌 / 时机效果）

内容（技能、卡牌、代号、牌组、时机规则、数值常量）全部是 `src/game/data/dsl/**` 下的 JSON，
由 `src/game/dsl/**` 的**单一解释器**执行：

- **词表与类型**：`dsl/kinds.ts`（判别式词表，唯一事实来源）+ `dsl/types.ts`（IR 类型）。
- **字段表单一事实源**：`dsl/fieldSpecs.ts` 声明「哪个节点/判别式允许哪些字段、各是什么类型」，
  校验器与 schema 生成器读同一份表；漏改任一边由**编译期断言**拦下。
- **加载期校验**：`dsl/validate/`（按职责分文件）拒绝未知键/未知判别式/悬空引用/死文档/费用 < 1 等，
  一次报出全部问题（`DslLoadError` 带 JSON 路径）；`dsl/registry.ts` 导入即校验。
- **求值**：`dsl/value.ts`（数值表达式 + 修正通道聚合）、`dsl/condition.ts`（条件，可带 `reason` 失败说明）、
  `dsl/target.ts`（目标选取，含多目标 `count` 与 `resolveTargetChoices`）、`dsl/template.ts`（战报模板）。
- **执行**：`dsl/effect.ts` 是全部效果指令的唯一入口（含逐个目标执行的 `for-each-target`），`dsl/primitives.ts` 提供牌区/体力/威胁/能量/帧等引擎原语；
  `dsl/event.ts` 把"规则文档 + 技能触发"统一到同一套时机派发上，触发**收集**在 `dsl/triggers.ts`
  （不依赖解释器，因此引擎原语可以放心地用，不会形成循环依赖）。
- **效果树查询**：`dsl/effects.ts` 提供 `effectsInclude` / `effectsHarmChosenTarget` 等结构查询，
  AI 的用途判定与注册表的卡牌角色派生共用一份递归形状。
- **规范文本**：`docs/dsl.md`（节点全表、语义、扩展指南）；`data/dsl/schema.json` 由
  `dsl/schema.ts` 从 `fieldSpecs.ts` **生成**，`schema.test.ts` 逐字节比对防止漂移。

扩展的验收标准：**新增技能 / 卡牌 / 代号 / 奖励参数只需要加 JSON**，引擎、legality、AI、界面一行都不用改——
`dsl/extensibility.test.ts` 用一个全新主动技、一张全新攻击牌（含牌组与守恒）、一次体力上限调整、**一张使用时选目标的牌**、**一张多目标牌**与**一张带 `upgradeTo` 的牌**做了端到端验证。

## 目录结构

```
src/
  game/                    # 规则引擎（纯 TS，不依赖 Vue）
    types.ts               # 领域类型：Card / VirtualCard / Prompt / Action / Frame / Phase / GameState
    engine/                # index（submit / isOver 门面）+ setup（抽将建局）
                           # stack（结算帧栈与推进循环）+ actions（各动作的 applier）
    rng.ts                 # mulberry32 + 种子化洗牌（可复现）
    log.ts                 # 中文战报
    testUtils.ts           # 测试用状态构造器
    data/                  # 内容视图：species / cardDefs / deck（实时由 DSL 注册表派生）
      dsl/                 # **内容文档**：ruleset、rules、decks、cards、skills、species + schema.json
    dsl/                   # **DSL 运行时**
                           # kinds（词表）· types（IR）· fieldSpecs（字段表唯一来源）
                           # validate/（分文件校验器：fieldTables/primitives/四类节点/docs/refs）
                           # registry · runtime · value · condition · target · modifier
                           # template · effect（解释器）· primitives（引擎原语）
                           # triggers（触发收集）· event（时机派发）· effects（效果树查询）
                           # schema（JSON Schema 生成器）
    rules/                 # phase（六阶段、时机、跳过/额外阶段）
                           # turn（回合推进、摸牌数、手牌上限、回合结束威胁结算）
                           # threat（叠加／抵消威胁、威胁不变式 —— 基础伤害机制）
                           # energy（能量消耗、回满、能量不变式）
                           # reward（奖励池、抽候选、升级/移除/回复的纯逻辑）
                           # usage（使用次数统计与「每回合限一次」技能记录）
                           # legality / damage / dying / death / cardZones / distance
    skills/                # index（牌面生成、主动技枚举、目标选择解析、通道读取）
    ai/                    # 规则式 AI（按文档派生的用途决策、奖励决策与选目标，确定性）
  stores/                  # 界面状态层：game.ts 是唯一 barrel（export * 转发下面六个模块）
    state.ts               # 只有 ref：screen / draftOptions / gameState / 选择态（叶子）
    selectors.ts           # 只读派生：按钮列表、文案、目标选择器、奖励候选与可用性
    actions.ts             # act 与各 submit：唯一清空选择态、捕获 RuleError 的地方
    aiDriver.ts            # AI 驱动循环与 pumpToken 竞态守卫（唯一的异步副作用）
    selection.ts           # 手牌选择与目标选择态（先进入选择态再提交）
    session.ts             # 抽将 / 开局 / 回首页（三个入口都先让旧 AI 回调失效）
  components/              # StartScreen / DraftScreen / GameBoard / PlayerPanel / HandCard
                           # ActionBar / PromptOverlay / RewardOverlay / LogPanel / HealthBar
```

引擎以 **prompt 驱动的状态机**对外：`submit(state, action)` 先校验再应用，然后 `advance()` 自动推进系统步骤，直到停在需要人或 AI 决策的点上。回合推进由 `(阶段, 子步骤)` 游标加剩余阶段队列 `phaseQueue` 表示，规则效果按「时机」注册。界面用 `reactive()` 包裹同一份状态对象，引擎就地修改它即自动刷新，引擎本身永远不 import Vue。

## 已知简化

- **卡牌没有花色与点数**：`Card` 只有 `uid` 与 `kind`，费用与效果都按牌种固定（费用可被 `card-cost` 通道修正，下限恒为 1）。
- **无随机判定**：没有任何需要翻牌判定的机制；唯一的随机来源是洗牌（`rng.ts`），技能只依赖牌种、手牌数与威胁。
- **威胁不跨回合累积**：每个威胁只在「施加者回合 → 承受者回合结束」之间存活一轮，回合结束时无论如何都会清空（兑现为伤害或已被抵消）。因此不存在「攒威胁一波带走」的长线玩法。
- **伤害来源不逐笔追踪**：承受者回合结束结算伤害时，`DamageCtx.source` 直接记 1v1 的唯一对手。若同一回合里既有对手的威胁又有自己【风暴】的威胁，自伤也会被记成「对手造成」——当前内容不依赖这个字段的精确来源。
- **手牌上限按结算前的体力算**：弃牌阶段在「回合结束时威胁结算」之前，所以本回合的威胁伤害不会影响本回合要弃几张牌。
- **能量不跨回合累积**：没有「存能量」的概念，回合开始时只是回复至上限，多出来的部分不会保留；因此留能量过回合没有意义，进攻与抵消都用当回合的能量。
- **技能不消耗能量**：【强袭】以及弃牌都不付能量（主动技的代价写在文档的 `costCards` / 效果里，当前都没有能量费用）。
- **濒死即阵亡**：内容层已删除全部回血牌，没有任何牌声明 `dying` 语境，因此进入濒死就只能放弃、随后阵亡；引擎的救援链路（`dying` 语境 + `resolve-dying`）仍在，由测试注入的合成牌 `test-mend` 守护。
- **判定 / 准备 / 结束阶段为空**：本作没有需要判定的内容，这三个阶段保留为空阶段与时机扩展点。
- **无额外回合**：阶段层面支持「跳过阶段 / 额外的阶段」，但还没有「额外回合」；将来加入时挂在「回合结束时」的时机上。
- **对抗机制是占位**：`contest` / `contest-contribute` 指令、`respond` 询问、`play-card` 动作、卡牌 `play` 变体与 `defend-need-against` 通道全部保留，但**没有任何内置内容使用**（详见上文「对抗机制（占位）」）；它由合成内容的测试守护，不是活的防御手段。
- **牌池十六张牌（3 基础 + 10 奖励 + 3 升级版），没有装备与多目标响应链**：基础牌在牌组里，奖励新卡只能靠三选一获得；多目标只是「同时作用于全部候选」，没有「多目标 + 逐个响应」的对抗链；加牌仍然只需要一份 JSON（见 `dsl/extensibility.test.ts`）。
- **奖励候选双方共享同一组**：一次 `offer-reward` 只抽一次候选（帧上存 `cards`），双方看到并从中选同一组牌；抽到就走 rng，因此同种子仍然逐行复现。
- **奖励没有重抽与锁定**：卡牌奖励只能「选一张」或「跳过」，服务奖励必须三选一（三项都不可用时该玩家自动跳过并记战报）；没有「刷新候选」「锁定一张下次再选」这类机制。
- **移除区只进不出**：被移除的牌计入牌数守恒、不再参与摸牌，也不能被再次升级/移除；没有「回收移除牌」的机制。
- **多目标只支持卡牌的使用变体**：`TargetSpec.count` 出现在主动技的 `target` 上会被校验器以 `bad-combination` 拒绝（主动技仍是单选）；`exactly` 模式必须显式给目标，`all` 模式不接受只给一部分。
- **多目标下不绑定 `target`**：声明了 `count` 的变体，效果里的 `target` 引用必须写在 `for-each-target` 内（加载期守卫），否则会在更深处抛错或只作用于第一个目标。
- **`for-each-target` 的上下文不冒泡**：每次迭代用子上下文，迭代内的 `{amount}` / `{picked}` 不会传给外层效果。
- **对称威胁不再有「同归于尽」**：伤害只在各自的回合结束时结算，而回合是交替的，因此不可能同一时刻双方归零；【风暴】的对称威胁由双方各自在自己的回合结束时兑现（谁先结算谁先可能阵亡）。
- **数值旋钮都在内容文档里**：能量上限、每张【打击】的威胁、摸牌数、手牌上限偏移、费用偏移、攻击范围（`defend-need-against` 只服务占位对抗）七条通道全部由引擎消费（`dsl/channels.test.ts` 守卫），改 `data/dsl/rules/base.json` 的基准值或加一条技能 `modifiers` 就能改数值；引擎里只剩夹取规则（费用恒 ≥ 1、威胁恒 ≥ 0、抵消不溢出）。
- **牌组私有但张数仍按全局守恒**：内容层已经没有跨池取牌的牌，但引擎仍按「全局 `cardTotal` 张、uid 唯一」守护（开局 24 张，奖励会动态加牌）——`engine.test.ts` 用一份合成技能验证「牌易主后归属获得者」这条口径没有退化。
- **三套牌组按代号分化**：`basic`（反击型）、`aggressive`（进攻型、转化型）、`guarded`（防御型）；改牌组只需新增/替换牌组 JSON 并改代号文档的 `deck` 字段。
- **距离恒为 1**：1v1 双方座位距离固定；攻击范围走 `attack-range` 通道（基准 1），`rules/distance.ts` 保留完整接口以便扩展多人。
- **濒死询问顺序**：从濒死者开始按座次询问（1v1 即濒死者 → 对手），`util.ts` 的 `aliveOrderFrom` 是顺序扩展点。
- **`scope: any` 的目标选择机制保留**：内置内容已无这类牌（回血牌删除），机制由合成牌 `test-aid` 的测试守护；将来新增「任意已受伤角色」类内容时目标选择器会自动列出全部候选。
- **AI 是规则式的，会做牌组循环**：有威胁时先打【防御】抵消（威胁致命时不保留同类牌），再花剩下的能量进攻；濒死无人可救就放弃、弃牌按「攻击→防御→回复」优先级；自伤牌按「收益 − 自伤」判断，并会把**已有威胁**一起算进自伤代价（扛不住就绝不打）；功能牌（抽牌 / 弃对手手牌 / 额外阶段）按文档结构在合适条件下使用。奖励决策由文档结构派生：卡牌按「威胁/治疗/抵消/摸牌的量 ÷ 费用」评分选最高（低于阈值且允许跳过时跳过）；**服务奖励优先「移除」未升级的初始牌**（牌组越薄、关键牌上手率越高），只有体力 ≤ 3 时才先回复、移除被下限挡住时才升级。它不会做长线规划（例如不知道「下回合对手可能有几张【防御】」）。
- **AI 不认技能/牌种 id**：用途（治疗、换牌、攻击、防御、回复、进攻主动技、功能牌、奖励评分）由文档结构派生（`cardRole` / `skillKinds` / `effectsInclude` / `findEffect`），策略阈值留在 `ai/index.ts`（`CYCLE_MIN_HP` / `OFFENSE_RESERVE` / `UTILITY_DRAW_MAX_HAND` / `SELF_HARM_MARGIN` / `REWARD_MIN_SCORE` / `REWARD_DANGER_HP` 等）。
- **内容随应用打包**：`data/dsl/*.json` 由 `import.meta.glob` 静态打包并在启动时校验，**不支持运行时热加载**；注册表与加载是解耦的（`createRegistry` / `withRegistry`），将来要做内容包只需再加一个加载器。
- **可选发动的触发技能只支持「受到伤害后」**：`optional: true` 目前仅允许 `after-damage`（引擎在回合结束的威胁结算里 emit 的事件类时机），其余时机只能是非可选效果。

### 平衡观察

用 200 局 AI 自对局统计（**删除回血牌 + 12 张初始牌 + 每回合摸 5 张 + AI 主动删牌**落地后重测；口径与 `engine.test.ts` 的 200 局自对局骨架一致——双方都由 AI 驱动、同种子可复现；【打击】次数按战报中「使用【打击…」的行数统计）：

| 指标 | 数值 |
|---|---|
| 中位局长 | 19 回合 |
| 平均局长 / 最短 / 最长 | 18.9 / 8 / 31 |
| 打到消耗战（≥ 21 回合）的比例 | 38% |
| 平均每局【打击】次数 | 21.9 |
| 平均每局奖励选择 / 升级 / 移除 / 回复 | 11.8 / 0.0 / 7.5 / 1.1 |
| 先手胜率 | 52% |
| 代号胜场 | 防御型 79 > 转化型 72 > 进攻型 49 > 反击型 0 |

观察：

- **节奏仍在目标区间**：中位 19 回合（16~22）。摸牌从 2 提到 5、牌组从 20 缩到 12，但删掉回血后对局没有变长。
- **消耗战收尾 38%**：接近 40% 上限。回血牌删除后伤害几乎不可逆，长局更容易被消耗战终结。
- **AI 的删牌策略生效**：平均每局 7.5 次「移除」、0 次「升级」——AI 优先删掉未升级的初始牌，牌组被削到下限附近，奖励里的「升级」在 AI 自对局中几乎不再被选中（人类玩家仍可选）。这符合本次「牌组循环」的要求，但也意味着**升级机制基本不参与 AI 的决策**；若希望 AI 兼顾升级，可调 `ai/index.ts` 的 `REWARD_DANGER_HP` 附近的服务优先级。
- **反击型崩盘（0 胜 / 200）**：本次改动最严重的平衡问题。新规则奖励「高能量 + 薄牌组」：【蓄能】【转换】各 +2 能量、进攻型有【强袭】白嫖 2 点威胁，而反击型既无能量加成、又只能在挨打后反击 1 点，在 12 张牌、每回合摸 5 张的快节奏里没有输出手段。**这不是 AI 删牌造成的**：把 AI 改回「升级优先」后反击型也只有 1 胜 / 200。修复需要内容数值（`skills/riposte.json` 等），本次按指示未擅自改动，等你确认方向。
- **先手胜率 52%**：落在 45%~58% 区间内。

可调旋钮（改完记得同步测试期望值）：

- `src/game/data/dsl/species/*.json`：代号体力上限（现统一 `maxHp: 10`）与牌组引用。
