# 协同进化（Coevolution）· 1v1 单挑

以物种为单位的 1v1 卡牌对战：每个物种拥有自己的 20 张私有牌组，用五张牌（打击 / 防御 / 回复 / 急救 / 风暴）决出胜负。
纯前端单机，玩家操作一方，另一方由规则式 AI 驱动。

- 技术栈：Vue 3 + TypeScript + Vite 8 + Tailwind CSS v4
- 规则引擎：纯 TypeScript、零 Vue 依赖、状态可序列化、随机确定性
- 测试：vitest 单元测试（322 个用例，含 200 局 AI 自对局不变式校验）

```bash
npm install
npm run dev     # 开发服务器
npm test        # 运行全部测试
npm run build   # 类型检查 + 生产构建
```

## 卡牌

卡牌只有**卡面效果**与**费用**：没有花色，也没有点数——`types.ts` 的 `Card` 只有 `uid` 与 `kind`，
效果与费用都写在 `data/cardDefs.ts`，同名卡牌之间完全等价。

### 五张牌

| 牌 | 能量 | 卡面效果 |
|---|---|---|
| **打击** | 1 | 对对方造成 1 点伤害；其可打出【防御】抵消。**没有次数限制**，有多少能量就能打几张。 |
| **防御** | 1 | 抵消一次【打击】。只能在响应时打出。 |
| **回复** | 2 | 回复 1 点体力。出牌阶段只能对自己使用且需已受伤；濒死时可用来自救。 |
| **急救** | 2 | **使用时选择目标**：令一名已受伤的角色（可以是自己）回复 1 点体力。 |
| **风暴** | 2 | **多目标**：对每名角色（包括你自己）造成 1 点伤害，不能被【防御】抵消。 |

费用是**按牌种的固定值**（`data/cardDefs.ts` 的 `cost`）：打击 1 / 防御 1 / 回复 2 / 急救 2 / 风暴 2。

【急救】与【风暴】分别验收了两条机制：**使用卡牌时选目标**（`UseVariant.target`，
与主动技共用 `cardTargetChoice`）与**多目标**（`TargetSpec.count` + `for-each-target`）。
两张牌都只是 JSON，引擎、legality、AI 与界面里没有任何牌种分支。

### 私有牌组（每物种 20 张，三套）

| 牌组 | 构成 | 物种 |
|---|---|---|
| `basic` | 打击 11 / 防御 6 / 回复 3 | 🦌 鹿、🐺 狼、🦊 狐 |
| `aggressive` | 打击 11 / 防御 5 / 回复 2 / 急救 1 / 风暴 1 | 🐯 虎、🐆 豹、🦁 狮 |
| `guarded` | 打击 10 / 防御 7 / 回复 3 | 🐻 熊、🐂 牛 |

牌组是**私有**的：每个物种（即每位玩家）拥有自己的 20 张牌组与自己的弃牌堆，摸牌只从自己的牌组摸，
自己的牌组耗尽时也只把**自己的**弃牌堆洗回自己的牌组，双方互不干扰。

按物种分化牌组只需新增/替换一份牌组 JSON 并改物种文档的 `deck` 字段：uid 分配（玩家 0 从 0 起、玩家 1 接续）与守恒校验都由牌组文档推导，不需要改代码。
三套牌组是平衡旋钮（见文末「平衡观察」）：防守牌组给熊与牛更多【防御】，攻击牌组给虎、豹、狮【急救】与【风暴】但少一张【防御】。

### 基础规则术语

| 术语 | 含义 |
|---|---|
| 阶段 | 回合被划分成的固定步骤，顺序为准备 → 判定 → 摸牌 → 出牌 → 弃牌 → 结束 |
| 时机 | 引擎在固定时点执行规则效果的位置，如「回合开始时」「阶段开始时」「阶段结束时」 |
| 摸牌数 | 摸牌阶段摸几张牌，默认 2 张（`draw-count` 通道基准）；先手角色的第一回合 1 张；技能可按通道修正 |
| 手牌上限 | 弃牌阶段结束时允许保留的手牌数，默认等于当前体力值（`hand-limit` 通道是相对体力的偏移，基准 0） |
| 能量 | 使用／打出卡牌要支付的资源，按牌种费用加 `card-cost` 通道修正计（**下限恒为 1**）；**回合开始时回复至上限**（默认 3 点） |
| 上限 | 能量的最大值，由基础值加技能修正得来（【怒吼】+2） |
| 跳过阶段 / 额外的阶段 | 本回合计划中删去某个阶段，或额外插入一个阶段 |

## 对局流程

1. 开局从 8 个物种中随机抽 3 个，玩家选 1 个；AI 从剩余物种中随机选 1 个。
2. 双方各自洗一副 20 张的私有牌组，各摸 4 张起手牌；玩家先手，**先手第一回合少摸 1 张**，此后每回合摸 2 张。
3. 回合流程（六阶段）：
   **回合开始时 → 准备阶段 → 判定阶段 → 摸牌阶段 → 出牌阶段 → 弃牌阶段 → 结束阶段 → 回合结束时**。
   - 每个阶段再分为「阶段开始时 → 阶段进行 → 阶段结束时」，规则效果注册在时机上（`rules/phase.ts`）；引擎**先把游标移到下一个子步骤再产生效果**，所以濒死等结算打断流程后不会重复执行同一个子步骤。
   - 摸牌阶段：默认摸 2 张（先手第一回合 1 张）。
   - 出牌阶段：能量在回合开始时已回满，能付几张【打击】就打几张（没有次数限制）；【回复】仅对自己且需已受伤；可发动主动技。
   - 弃牌阶段：手牌上限 = 当前体力值，超出部分须弃置。
   - 准备 / 判定 / 结束阶段本作没有可结算的内容，保留为空阶段与时机扩展点。
   - 阶段可被**跳过**（`skipPhase`）或插入**额外的阶段**（`addExtraPhase`），作用于本回合剩余的阶段计划 `state.phaseQueue`。
4. **单将决胜**：任意一方体力归零即败。

### 结算链（完备性说明）

- **使用【打击】**：合法性校验（牌面选项 + **能量是否够付** + **目标是否合法**）→ 支付能量 → 指定目标 → 询问目标打出【防御】（【威压】为 2 张，逐张询问）→ 抵消或造成 1 点伤害 → 结算收尾。
- **使用卡牌时的目标选择**：【打击】（唯一候选对手）、【回复】（自己 / 濒死者）沿用文档缺省目标；
  【急救】声明了 `target`（`scope: any` + 已受伤条件）且候选不唯一时必须由玩家选定，
  界面进入目标选择态后再提交（`Action.use-card.targets`）。可用性与提交共用 `cardTargetChoice`，**按得到就必然提交得成**。
- **多目标**：`TargetSpec.count` 支持 `all`（作用于全部合法候选，如【风暴】同时打双方）与 `exactly`（必须选够 N 个）。
  多目标变体的效果写在 `for-each-target` 指令里，逐个把 `target` 绑定为当前目标执行；
  多目标下**不绑定** `target`，直接引用会在加载期被校验器拒绝，避免"以为打了全体却只打了一个"。
- **伤害结算顺序**：`damage.before`（预留钩子）→ 扣减体力 → 写入伤害上下文 → 「受到伤害后」技能（【夺食】／【狡计】，人类玩家可选发动）→ 濒死检查。
  造成伤害的牌在整条链走完之前一直留在**处理区**，这正是【夺食】能把牌取回手牌的原因；结算完全结束后才进入弃牌堆。
- **处理区带归属**：一次【打击】的收尾要同时处理攻方的打击牌与守方的防御牌，而弃牌堆是私有的，因此处理区每个条目都记录 `owner`，收尾时**分别**进入各自的弃牌堆。
- **濒死**：从濒死者开始按座次询问所有存活角色是否使用【回复】；可连续使用直到体力回到 1 以上；队列耗尽则死亡。**濒死中的【回复】不受「仅自己／已受伤／出牌阶段」限制，但仍然要付 2 点能量**。
- **死亡**：标记阵亡 → 弃置全部手牌（进自己的弃牌堆）→ 清空结算栈与处理区（按条目归属分流）→ 判定胜负。
- **「失去体力」≠「受到伤害」**：【透支】的体力流失不会触发【夺食】／【狡计】，但同样会进入濒死。
- **牌数守恒**：任意结算步之后，双方**合计 40 张**牌各自恰好属于「自己的牌组／手牌／自己的弃牌堆／处理区」之一，且 uid 全局唯一，引擎在每次 `submit` 后自动校验。
  口径是**全局**而非「每方恒为 20 张」：【夺食】会把对手的牌拿进自己手里，之后再弃置就归获得者的弃牌堆，双方池子的张数会此消彼长，但总额不变。
- **牌组耗尽**：某方把自己的弃牌堆洗回自己的牌组；两者同时为空则跳过摸牌并记录日志。

结算顺序由显式的**结算帧栈**驱动（`strike → damage → dying → flush`），而不是散落的回调，因此顺序可测、可读、可扩展。

### 能量系统

| 规则 | 内容 |
|---|---|
| 上限 | 每人 3 点；【怒吼】+2（熊 5 点） |
| 回复 | **回合开始时回复至上限**，只回复回合角色的能量；没花完的余额留在池中（不超过上限） |
| 付费范围 | **所有使用与打出**：出牌阶段使用、响应【打击】打出【防御】、濒死使用【回复】（救援者付自己的能量） |
| 费用 | 按「**当作的牌面**」计：打击 1 / 防御 1 / 回复 2 |
| 不付费 | 主动技（疗愈／透支）、弃牌阶段的弃置、疗愈的弃牌 |

三个直接推论：

1. **防御要预留能量**。能量只在自己回合开始时回满，所以拦截对手【打击】用的是你上回合没花完的部分——「这回合多打两张」与「留 1 点防守」是一对取舍。AI 也按这条行事（手上有能打出的【防御】时留 1 点）。
2. **濒死自救要付 2 点能量**。把能量打光之后被打进濒死，就可能没有能量自救而阵亡。
3. **【打击】的次数限制由能量接管**。同一回合可以连打多张【打击】，上限是能量而不是次数；相应地，**任何牌面的费用都不允许为 0**（0 费 + 无次数限制 = 无限连击，`energy.test.ts` 对此有断言）。

能量与「牌数守恒」一样是硬不变式：任意结算步之后必须落在 `0..上限` 之内，引擎在每次 `submit` 后自动校验（`assertEnergyBounds`）。

参数在 `src/game/rules/energy.ts`（`BASE_ENERGY_MAX`）与 `src/game/data/cardDefs.ts`（每张牌的 `cost`）。

### 消耗战（终止规则，重要）

五张牌的 1v1 存在天然的僵持：鹿每回合回 1 点刚好抵消每回合 1 点伤害，【疾影】可以把每次【打击】都转成【防御】挡掉，而牌组会无限洗回，于是对局可以永远打下去。能量系统让「双方都攒着能量不进攻」成为另一种僵持：谁先动手谁吃亏。

因此从**第 21 回合**起进入消耗战：每个回合的「回合开始时」时机，回合角色失去体力，每 5 回合递增 1 点（`1 + ⌊(回合 − 21) / 5⌋`）。流失量无上限增长，最终必定超过任何回复能力，保证对局必然结束。能量的回满发生在这条效果之前，所以因消耗战进入濒死的角色是带着满能量被询问的。

消耗战不是写在流程里的特例，而是**一条 DSL 规则文档**：`src/game/data/dsl/rules/attrition.json`
挂在「回合开始时」时机上，与技能触发走同一条通路（`dsl/event.ts` 的时机派发）。
回合数、递增步长、流失量表达式都在文档里；`rules/turn.ts` 只保留 `ATTRITION_TURN` /
`ATTRITION_STEP` / `attritionLoss()` 供界面提示与测试断言，并由 `turn.test.ts` 断言两者一致。

## 物种与技能

| 物种 | 体力 | 技能 | 类型 | 效果 |
|---|---|---|---|---|
| 🐯 虎 | 4 | **猛扑** | 主动 | 出牌阶段限一次：弃置一张手牌，对对方造成 1 点伤害（不能被【防御】抵消） |
| 🐻 熊 | 4 | **怒吼** | 常驻 | 你每回合的能量上限 +2（3 → 5） |
| 🐆 豹 | 4 | **疾影** | 转化 | 你可以将【打击】当【防御】、【防御】当【打击】使用或打出 |
| 🐺 狼 | 4 | **夺食** | 触发 | 当你受到伤害后，你可以获得造成此伤害的牌 |
| 🦌 鹿 | 3 | **疗愈** | 主动 | 出牌阶段限一次，弃一张手牌，令一名已受伤的角色回复 1 点体力 |
| 🦁 狮 | 3 | **威压** | 常驻 | 你使用【打击】时，目标需依次打出两张【防御】才能抵消 |
| 🐂 牛 | 4 | **透支** | 主动 | 出牌阶段，你可以失去 1 点体力，然后摸两张牌 |
| 🦊 狐 | 3 | **狡计** | 触发 | 当你受到伤害后，你可以获得伤害来源的一张手牌 |

原【猛扑】（虎）与原【灵草】（鹿）都靠「红色牌」判定，卡牌去掉花色后**整条移除**；
虎因此一度没有技能，本阶段补上了不依赖花色的新【猛扑】（主动技，弃牌造成不可被【防御】抵消的伤害），鹿保留【疗愈】，豹的【疾影】按牌种转化，不受影响。

上表的每个技能都是**一份 JSON 文档**（`src/game/data/dsl/skills/*.json`），行为由 DSL 解释器执行；
引擎、合法性判定、AI、界面里**不存在任何技能 id 分支**（由 `dsl/guards.test.ts` 机械守卫）。

转化型技能产生的牌统一用 `VirtualCard` 表示（`as` = 当作什么牌，`source` = 实际消耗的牌，`via` = 技能），响应、伤害、日志、弃牌全部只认它，避免结算与展示分叉。

## 内容 DSL（技能 / 卡牌 / 时机效果）

内容（技能、卡牌、物种、牌组、时机规则、数值常量）全部是 `src/game/data/dsl/**` 下的 JSON，
由 `src/game/dsl/**` 的**单一解释器**执行：

- **词表与类型**：`dsl/kinds.ts`（判别式词表，唯一事实来源）+ `dsl/types.ts`（IR 类型）。
- **加载期校验**：`dsl/validate.ts` 拒绝未知键/未知判别式/悬空引用/死文档/费用 < 1 等，
  一次报出全部问题（`DslLoadError` 带 JSON 路径）；`dsl/registry.ts` 导入即校验。
- **求值**：`dsl/value.ts`（数值表达式 + 修正通道聚合）、`dsl/condition.ts`（条件，可带 `reason` 失败说明）、
  `dsl/target.ts`（目标选取，含多目标 `count` 与 `resolveTargetChoices`）、`dsl/template.ts`（战报模板）。
- **执行**：`dsl/effect.ts` 是全部效果指令的唯一入口（含逐个目标执行的 `for-each-target`），`dsl/internal.ts` 提供牌区/体力/能量/帧等引擎原语；
  `dsl/event.ts` 把"规则文档 + 技能触发"统一到同一套时机派发上。
- **规范文本**：`docs/dsl.md`（节点全表、语义、扩展指南）；`data/dsl/schema.json` 由
  `dsl/schema.ts` 从词表与字段表**生成**，`schema.test.ts` 逐字节比对防止漂移。

扩展的验收标准：**新增技能 / 卡牌 / 物种只需要加 JSON**，引擎、legality、AI、界面一行都不用改——
`dsl/extensibility.test.ts` 用一个全新主动技、一张全新攻击牌（含牌组与守恒）、一次体力上限调整、**一张使用时选目标的牌**与**一张多目标牌**做了端到端验证。

## 目录结构

```
src/
  game/                    # 规则引擎（纯 TS，不依赖 Vue）
    types.ts               # 领域类型：Card / VirtualCard / Prompt / Action / Frame / Phase / GameState
    engine.ts              # createGame / rollDraft / getPending / submit / advance
    rng.ts                 # mulberry32 + 种子化洗牌（可复现）
    log.ts                 # 中文战报
    testUtils.ts           # 测试用状态构造器
    data/                  # 内容视图：species / cardDefs / deck（实时由 DSL 注册表派生）
      dsl/                 # **内容文档**：ruleset、rules、decks、cards、skills、species + schema.json
    dsl/                   # **DSL 运行时**：kinds/types/validate/registry/value/condition
                           # target/modifier/template/internal/effect/event/schema
    rules/                 # phase（六阶段、时机、跳过/额外阶段）
                           # turn（回合推进、摸牌数、手牌上限）
                           # energy（能量消耗、回满、能量不变式）
                           # usage（使用次数统计与「每回合限一次」技能记录）
                           # legality / damage / dying / death / cardZones / distance
    skills/                # index（牌面生成、主动技枚举、目标选择解析、通道读取）
    ai/                    # 规则式 AI（按文档派生的用途决策与选目标，确定性）
  stores/game.ts           # reactive 状态 + 目标选择态 + AI 驱动循环（pumpToken 防竞态）
  components/              # StartScreen / DraftScreen / GameBoard / PlayerPanel / HandCard
                           # ActionBar / PromptOverlay / LogPanel / HealthBar
```

引擎以 **prompt 驱动的状态机**对外：`submit(state, action)` 先校验再应用，然后 `advance()` 自动推进系统步骤，直到停在需要人或 AI 决策的点上。回合推进由 `(阶段, 子步骤)` 游标加剩余阶段队列 `phaseQueue` 表示，规则效果按「时机」注册。界面用 `reactive()` 包裹同一份状态对象，引擎就地修改它即自动刷新，引擎本身永远不 import Vue。

## 已知简化

- **卡牌没有花色与点数**：`Card` 只有 `uid` 与 `kind`，费用与效果都按牌种固定（费用可被 `card-cost` 通道修正，下限恒为 1）；由此**依赖花色的技能一并移除**（原【猛扑】、原【灵草】），虎在本阶段换上了不依赖花色的新【猛扑】。
- **无随机判定**：没有任何需要翻牌判定的机制，技能只依赖牌种与手牌数（唯一的随机是【狡计】取哪张手牌）。
- **能量不跨回合累积**：没有「存能量」的概念，回合开始时只是回复至上限，多出来的部分不会保留。
- **技能不消耗能量**：【疗愈】【透支】【猛扑】以及弃牌都不付能量（主动技的代价写在文档的 `costCards` / 效果里，当前都没有能量费用）。
- **濒死可能因能量不足而救不回来**：濒死【回复】照常收 2 点能量，这是「所有使用与打出都消耗」的直接结果。
- **判定 / 准备 / 结束阶段为空**：本作没有需要判定的内容，这三个阶段保留为空阶段与时机扩展点。
- **无额外回合**：阶段层面支持「跳过阶段 / 额外的阶段」，但还没有「额外回合」；将来加入时挂在「回合结束时」的时机上。
- **牌池五张牌，没有装备与多目标响应链**：打击 / 防御 / 回复 / 急救 / 风暴；多目标只是「同时作用于全部候选」，没有「多目标 + 逐个响应」的对抗链；加牌仍然只需要一份 JSON（见 `dsl/extensibility.test.ts`）。
- **多目标只支持卡牌的使用变体**：`TargetSpec.count` 出现在主动技的 `target` 上会被校验器以 `bad-combination` 拒绝（主动技仍是单选）；`exactly` 模式必须显式给目标，`all` 模式不接受只给一部分。
- **多目标下不绑定 `target`**：声明了 `count` 的变体，效果里的 `target` 引用必须写在 `for-each-target` 内（加载期守卫），否则会在更深处抛错或只作用于第一个目标。
- **`for-each-target` 的上下文不冒泡**：每次迭代用子上下文，迭代内的 `{amount}` / `{picked}` 不会传给外层效果。
- **对称伤害同时归零时座位靠后者先阵亡**：多目标按座次推入伤害帧、结算栈后进先出，因此双方同时被打到 0 时，下标大的角色先完成死亡结算；1v1 里【风暴】同归于尽时先手座（下标 0）获胜。
- **数值旋钮都在内容文档里**：能量上限、抵消张数、摸牌数、手牌上限偏移、费用偏移、攻击范围六条通道全部由引擎消费（`dsl/channels.test.ts` 守卫），改 `data/dsl/rules/base.json` 的基准值或加一条技能 `modifiers` 就能改数值；引擎里只剩夹取规则（费用恒 ≥ 1）。
- **牌组私有但张数会漂移**：【夺食】把对手的牌拿进自己手里后，那张牌就归获得者所有（弃置 / 洗回都进获得者的牌区），因此双方池子不再各为 20 张，守恒口径是「全局 40 张、uid 唯一」。
- **三套牌组按物种分化**：`basic`（鹿、狼、狐）、`aggressive`（虎、豹、狮）、`guarded`（熊、牛）；改牌组只需新增/替换牌组 JSON 并改物种文档的 `deck` 字段。
- **距离恒为 1**：1v1 双方座位距离固定；攻击范围走 `attack-range` 通道（基准 1），`rules/distance.ts` 保留完整接口以便扩展多人。
- **濒死询问顺序**：从濒死者开始按座次询问（1v1 即濒死者 → 对手），`util.ts` 的 `aliveOrderFrom` 是顺序扩展点。
- **【疗愈】与【急救】可以治疗对手**：目标选择器列出文档允许的全部候选，玩家可以主动治疗对手（AI 只会治疗自己）。
- **【狡计】**：从伤害来源手牌中随机获得一张。
- **AI 是规则式的**：付得起就出【防御】、濒死不救对手、弃牌按「攻击→防御→回复」优先级；进攻时手上有能打出的【防御】就留 1 点能量防守。它不会做长线规划。
- **AI 不认技能/牌种 id**：用途（治疗、换牌、攻击、防御、回复、进攻主动技）由文档结构派生（`cardRole` / `skillKinds` / `effectsInclude`），策略阈值留在 `ai/index.ts`（`DEFENSE_RESERVE` / `CYCLE_MIN_HP` / `OFFENSE_RESERVE` 等）。
- **内容随应用打包**：`data/dsl/*.json` 由 `import.meta.glob` 静态打包并在启动时校验，**不支持运行时热加载**；注册表与加载是解耦的（`createRegistry` / `withRegistry`），将来要做内容包只需再加一个加载器。
- **可选发动的触发技能只支持「受到伤害后」**：`optional: true` 目前仅允许 `after-damage`（引擎会 emit 的事件类时机），其余时机只能是非可选效果。

### 平衡观察

用 200 局 AI 自对局统计（目标机制接通 + 虎获得【猛扑】+ 三套牌组之后重测；口径与 `engine.test.ts` 的 200 局自对局骨架一致——双方都由 AI 驱动、同种子可复现）：

| 指标 | 本阶段前 | 本阶段后 |
|---|---|---|
| 中位局长 | 14 回合 | 19 回合 |
| 平均局长 / 最短 / 最长 | 14.4 / 1 / 29 | 16.5 / 1 / 29 |
| 打到消耗战（≥ 21 回合）的比例 | 34% | 47% |
| 平均每局【打击】次数 | 17.0 | 17.3 |
| 先手胜率 | 49.5% | 49.0% |
| 物种胜场（200 局） | 狮 43 > 狐 34 > 鹿 32 > 熊 27 > 狼 25 > 豹 18 > 虎 13 > 牛 8 | 狐 32 > 熊 31 > 狮 31 > 鹿 30 > 虎 24 > 狼 20 > 牛 18 > 豹 14 |

胜场极差从 35 收到 18：

- **虎脱离垫底**（13 → 24）：【猛扑】每回合能把一张手牌换成 1 点不可被【防御】抵消的伤害，正好补上「攻击被【防御】兑掉」的缺口；攻击牌组再给它【急救】与【风暴】。
- **狮被拉回**（43 → 31）：移入攻击牌组（少一张【防御】）并把体力上限降到 3——【威压】把每次防守成本翻倍，只能用生存来还债。
- **牛与豹仍在低位**（18 / 14）：它们的问题是技能本身（【透支】在「能量才是闸门」的引擎里摸牌收益低，【疾影】依赖手里有【防御】可供转化），换牌组与调体力都推不动，需要下一次内容平衡专门处理。
- **代价是局长变长**：中位 14 → 19 回合、消耗战比例 34% → 47%（防守与治疗总量上升）。若要让对局更短，优先调 `decks/*.json` 的【回复】张数与 `rules/base.json` 的 `energy-max`。

本阶段另外调整了两条 AI 策略阈值（属于「怎么打」，不属于规则）：

- `CYCLE_MIN_HP`（3 → 4）：能量上限才是出牌数量的闸门，多摸的牌常常打不出去，因此只在满血附近才为摸牌失血——此前 AI 会一路失血自杀（牛从 8 抬到 18 有它一半功劳）。
- `OFFENSE_RESERVE = 2`：发动进攻型主动技（【猛扑】）后至少留 2 张手牌，不把最后的牌全押在一次进攻上；调到 3 会让虎从 24 掉到 15（本阶段试过并回退）。

可调旋钮（改完记得同步测试期望值）：

- `src/game/data/dsl/decks/*.json`：三套私有牌组的构成——调高【回复】会让消耗战更常见，调高【打击】会加快节奏。
- `src/game/data/dsl/rules/base.json`：六条通道的基准值，其中 `energy-max`（默认 3）调高会整体加快节奏。
- `src/game/data/dsl/cards/*.json`：每张牌的 `cost`（打击/防御 1，回复/急救/风暴 2）与效果（如【风暴】的伤害）。
- `src/game/data/dsl/skills/*.json`：技能数值（【怒吼】的 `energy-max` +2、【威压】的 `defend-need-against` set 2、【猛扑】的 `costCards` 与伤害）。
- `src/game/ai/index.ts`：`DEFENSE_RESERVE` / `CYCLE_MIN_HP` / `CYCLE_MAX_HAND` / `HAND_RESERVE` / `OFFENSE_RESERVE` / `HEAL_MAX_HP`——AI 策略不属于内容，仍在代码里。
- `src/game/data/dsl/species/*.json`：物种体力上限（`maxHp`）、技能表与牌组引用。
- `src/game/data/dsl/rules/attrition.json`：消耗战的起始回合（21）与递增步长（5）；`rules/turn.ts` 的 `ATTRITION_TURN` / `ATTRITION_STEP` 只是文档引用，由测试断言一致。
